# MushroomProcess shipment acknowledgment in ERP

MushroomProcess owns physical inventory and the confirmed reservation. Its
`mp_commerce_ship_products` entry point moves the scanned Products to Shipped
and records the movement and line/package IDs in the same database transaction.
It uses the existing Product location and acknowledgment functions. A failed
acknowledgment rolls back the scan's physical mutations. Use a stable movement
reference generated by the operator before a first attempt. This path does not
change the existing Ecwid or n8n fulfillment workflows.

ERP records a stock-neutral **Commerce External Receipt** linked to the submitted
Sales Order, plus shipped quantities by Woo line in Commerce Order State. It
does not create a Delivery Note, alter ERP stock, or mark Woo completed.
An ERP Delivery Note or accounting-stock policy needs an explicit reviewed Item
and warehouse mapping and is a future posting decision. A physical return uses
a separately reviewed operational path. Payment refunds do not reverse shipped
Products.

## Isolated acceptance

Use the dedicated test databases and ERP pairing from the unpaid-order runbook.
Apply MushroomProcess migration 055 and migrate the staged ERP app. Give the
operational role EXECUTE on `mp_commerce_ship_products(text,text,text,text,jsonb)`
and the minimum underlying package/acknowledgment privileges. The projection
worker needs read access to the shipment, order and ERP link ledger tables.
Use movement evidence only from committed MP rows.

Confirm a two-unit synthetic reservation with verified payment and linked
ERP documents. Set the following environment variables privately.
`SHIPMENT_LINES` is a JSON list containing `line_id` and the scanned
numeric `product_ids`. Use a saved movement reference and the matched Woo
order number in each command.

```bash
psql "$MP_TEST_DSN" -X -v ON_ERROR_STOP=1 -v order_id="$WOO_ORDER_ID" \
  -v movement="$MOVEMENT_REFERENCE" -v lines="$SHIPMENT_LINES" <<'SQL'
SELECT public.mp_commerce_ship_products('woocommerce', 'shop-test.danks.store',
                                       :'order_id', :'movement', :'lines'::jsonb);
SQL
```

Expect `partial` when one of the two units ships and `duplicate` for a replay.
Configure `commerce_mp_fulfillment_pilot` with `enabled: true` and a private
`movement_hmac` of at least 32 characters, shared only with the projection
worker as `COMMERCE_SHIPMENT_EVIDENCE_KEY`. Use a dedicated ERP Accounts Manager
or System Manager token.

```bash
python integrations/commerce/runtime.py reconcile-shipment \
  --config "$ORDER_INBOX_CONFIG" --order-key woocommerce shop-test.danks.store "$WOO_ORDER_ID" \
  --movement-reference "$MOVEMENT_REFERENCE"
```

Expect the same `shipment_receipt` and `sales_order` on each replay. Simulate a
lost ERP response and rerun the same command. Cancel the unshipped Woo quantity
through the normal webhook. Verify its hold is released, the shipped Product
remains at Shipped, and the committed shipment can still be reconciled. Disable
the isolated ERP fulfillment flag to suspend projection. Preserve committed
movement and receipt history.
